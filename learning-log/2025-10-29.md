### 1. Component Props and Callbacks
**What it is:** Components communicate with parent components through callback functions passed as props.

**Pattern:**
```typescript
// Child component accepts callback functions as props
interface ConversationListProps {
  conversations: Conversation[];
  onSelectConversation: (conversationId: number) => void;  // Callback
  onDeleteConversation: (conversationId: number) => void;  // Callback
  onNewChat: () => void;  // Callback
}

// Parent component passes handler functions
<ConversationList
  conversations={conversations}
  onSelectConversation={handleSelectConversation}  // Pass function
  onDeleteConversation={handleDeleteConversation}  // Pass function
  onNewChat={handleClearChat}
/>

// Child component calls the callback when user clicks
<button onClick={() => onDeleteConversation(conv.id)}>
  Delete
</button>
```

**Why This Pattern:**
- Child component doesn't need to know HOW to delete
- Parent component controls the behavior
- Reusable - same component can have different behaviors
- Clear separation of concerns

### 2. Array.reduce() for Grouping Data
**What it is:** A method to transform an array into a single value (often an object or another array).

**Our Use Case - Grouping Conversations by Date:**
```typescript
const groupedConversations = conversations.reduce((groups, conv) => {
  const category = formatDate(conv.created_at);  // "Today", "Yesterday", etc.

  if (!groups[category]) {
    groups[category] = [];  // Create array if doesn't exist
  }

  groups[category].push(conv);  // Add conversation to category
  return groups;  // Return accumulated result
}, {} as Record<string, Conversation[]>);

// Result:
// {
//   "Today": [conv1, conv2],
//   "Yesterday": [conv3],
//   "Last 7 Days": [conv4, conv5]
// }
```

**How reduce() Works:**
1. **Accumulator** (`groups`) - The result being built up
2. **Current Value** (`conv`) - Current item in array
3. **Initial Value** (`{}`) - Starting value for accumulator
4. **Return** - Updated accumulator for next iteration

**Visual Example:**
```typescript
// Iteration 1:
groups = {}
conv = { id: 1, created_at: "2025-10-29" }
category = "Today"
groups["Today"] = [conv]
return { "Today": [conv] }

// Iteration 2:
groups = { "Today": [conv1] }
conv = { id: 2, created_at: "2025-10-28" }
category = "Yesterday"
groups["Yesterday"] = [conv]
return { "Today": [conv1], "Yesterday": [conv] }

// ... and so on
```

### 3. TypeScript Record Type
**What it is:** A utility type for objects with string keys and consistent value types.

```typescript
Record<string, Conversation[]>
//     ^^^^^^  ^^^^^^^^^^^^^^^^
//     Key     Value type
//     type
```

**Equivalent to:**
```typescript
{
  [key: string]: Conversation[]
}
```

**Examples:**
```typescript
// Record<string, number> - object with string keys, number values
const scores: Record<string, number> = {
  alice: 100,
  bob: 95
};

// Record<string, string[]> - object with string keys, string array values
const tags: Record<string, string[]> = {
  post1: ["tech", "ai"],
  post2: ["news"]
};

// Our case - object with string keys (categories), Conversation array values
const grouped: Record<string, Conversation[]> = {
  "Today": [conv1, conv2],
  "Yesterday": [conv3]
};
```

**Why Use Record:**
- More readable than `{ [key: string]: Type }`
- TypeScript knows exactly what structure to expect
- Better auto-completion

### 4. Calculating Time Differences
**Pattern for "Today", "Yesterday", "Last 7 Days":**

```typescript
const formatDate = (dateString: string): string => {
  const date = new Date(dateString);
  const now = new Date();

  // Get difference in milliseconds
  const diffInMs = now.getTime() - date.getTime();

  // Convert to days
  const diffInDays = Math.floor(diffInMs / (1000 * 60 * 60 * 24));
  //                             ^^^^  ^^  ^^  ^^
  //                             ms    s   m   h

  if (diffInDays === 0) return 'Today';
  if (diffInDays === 1) return 'Yesterday';
  if (diffInDays <= 7) return 'Last 7 Days';
  return 'Older';
};
```

**Time Conversion Breakdown:**
```typescript
1 second = 1000 milliseconds
1 minute = 60 seconds = 60,000 ms
1 hour = 60 minutes = 3,600,000 ms
1 day = 24 hours = 86,400,000 ms

// So to convert ms to days:
days = milliseconds / (1000 * 60 * 60 * 24)
days = milliseconds / 86,400,000
```

### 5. Event.stopPropagation()
**Problem:** When you have nested click handlers, clicking the child triggers BOTH handlers.

```typescript
<div onClick={() => onSelectConversation(conv.id)}>  {/* Outer click */}
  <button onClick={() => onDeleteConversation(conv.id)}>  {/* Inner click */}
    Delete
  </button>
</div>

// Clicking "Delete" would:
// 1. Trigger onDeleteConversation ✓
// 2. Trigger onSelectConversation ✗ (unwanted!)
```

**Solution:** `stopPropagation()` prevents event from bubbling up to parent:

```typescript
<button onClick={(e) => {
  e.stopPropagation();  // Stop the click event from bubbling up
  onDeleteConversation(conv.id);
}}>
  Delete
</button>
```

**Why This Matters:**
- Without it, deleting a conversation would also select it
- Prevents confusing UI behavior
- Common pattern in nested clickable elements

### 7. Template Literals in className (JSX)
**Pattern:** Using template literals with conditionals for dynamic CSS classes.

```typescript
className={`base-classes ${
  condition ? 'class-if-true' : 'class-if-false'
}`}
```

**Our Example:**
```typescript
className={`group flex items-center justify-between p-2 rounded-lg cursor-pointer transition-colors ${
  currentConversationId === conv.id
    ? 'bg-gray-700'      // Highlighted style
    : 'hover:bg-gray-800' // Hover style
}`}
```

**Key Points:**
- Use backticks (`) for template literals
- Can embed JavaScript expressions with `${...}`
- Combine static classes with dynamic classes
- Ternary operator for conditional classes

**Common Mistake:**
```typescript
// ❌ WRONG - quotes around template literal
className='{`group flex...`}'

// ✅ CORRECT - no quotes, just curly braces
className={`group flex...`}
```

### 8. Tailwind CSS Group Hover Pattern
**What it is:** Showing/hiding child elements when hovering over parent.

```typescript
<div className='group'>  {/* Add 'group' class to parent */}
  <div>Conversation Title</div>

  {/* Child element - hidden by default, visible on parent hover */}
  <button className='opacity-0 group-hover:opacity-100'>
    Delete
  </button>
</div>
```

**How It Works:**
1. Add `group` class to parent element
2. Use `group-hover:*` classes on children
3. When parent is hovered, children with `group-hover:*` classes activate

**Our Use Case:**
- Trash icon is invisible (`opacity-0`)
- When hovering over conversation row, icon appears (`group-hover:opacity-100`)
- Cleaner UI - only show delete when needed

### 9. Python String Slicing for Titles
**Pattern:** Take first N characters of a string.

```python
text = "This is a very long conversation title"

# Take first 50 characters
title = text[:50]  # "This is a very long conversation title"

# Take first 50 characters, add ellipsis if longer
if len(text) > 50:
    title = text[:50] + "..."
else:
    title = text
```

**In Our Code:**
```python
def generate_conversation_title(messages: list[dict]) -> str:
    for message in messages:
        if message.get('sender') == 'user':
            text = message.get('text', '')
            if len(text) > 50:
                return text[:50] + "..."  # Truncate and add ellipsis
            return text
    return "New Conversation"
```

**Why 50 Characters:**
- Fits nicely in sidebar
- Enough to identify conversation
- Not so long that it wraps to multiple lines

## Challenges Faced

### Challenge 1: Variable Naming Typos
**Problem:** Multiple typos in variable names caused TypeScript errors.

**Examples:**
```typescript
// Line 41: Typo in state variable
const [conversatioins, setConversations] = useState...
//        ^^^^^^^^^^^^^ Missing 'n'

// Line 54: Wrong setter function
setConversationId(loadConversations);  // Wrong - expects number, not array

// Line 162: Typo in function name

//                   ^^^^^^^^^^^ Missing 's'
```

**Lesson:**
- TypeScript catches many errors, but not typos in initial declarations
- Variable naming consistency is crucial
- Use auto-complete to avoid typos (IDE suggests correct names)

### Challenge 2: Using Wrong Variable in Array Operations
**Problem:** Using `conversations` (empty state) instead of `loadedConversations` (just loaded data).

```typescript
const loadedConversations = await getUserConversations(user.id);
setConversations(loadedConversations);

// ❌ WRONG - conversations is still empty here!
const conv = conversations.find(c => ...);

// ✅ CORRECT - use the variable we just loaded
const conv = loadedConversations.find(c => ...);
```

**Why:**
- `setConversations()` doesn't update state immediately
- State updates happen after function finishes
- Must use the data variable, not the state variable

**Lesson:** When loading data, use the loaded variable immediately, not the state.

### Challenge 3: Template Literal Syntax in JSX
**Problem:** Added quotes around template literal in className.

```typescript
// ❌ WRONG
className='{`group flex...`}'
//         ^              ^  Extra quotes!

// ✅ CORRECT
className={`group flex...`}
```

**Why It's Wrong:**
- JSX uses `{}` for JavaScript expressions
- Template literals use backticks `
- Adding quotes makes it a string, not a template literal

**Lesson:** In JSX, `{}` means "JavaScript expression" - don't add extra quotes.

### Challenge 4: Understanding Promise Return Types
**Problem:** Confusion about whether `Promise<{ message: string }>` means returning the object or just the message.

**Clarification:**
```typescript
Promise<{ message: string }>  // Returns object: { message: "..." }
Promise<string>               // Returns string: "..."

// With Promise<{ message: string }>:
return response.json();  // Returns whole object

// With Promise<string>:
const data = await response.json();
return data.message;  // Extract and return just the string
```

**Lesson:**
- `Promise<Type>` describes the exact shape of the resolved value
- Must match what the backend sends
- Type is a contract between frontend and backend

### Challenge 5: Logging Format Error
**Problem:** Backend showed logging errors on startup:

```

```

**Cause:**
- Error in `logger.py` format string
- Format string had typo or incorrect placeholder

**Fix:** The logging still worked despite errors (errors were in how logs were formatted, not in actual functionality)

**Lesson:**
- Logging errors don't always break functionality

- Check format strings match Python logging requirements

## Key Takeaways

### 1. Component Props Are Function Parameters
Props in React/TypeScript are just like function parameters:

```typescript
// Function with parameters
function greet(name: string, age: number) {
  console.log(`Hello ${name}, age ${age}`);
}

// Component with props (same concept!)
function Greeting({ name, age }: { name: string; age: number }) {
  return <div>Hello {name}, age {age}</div>;
}
```

**Lesson:** If you understand functions, you understand components!

### 2. Array Methods Are Powerful
- `.map()` - Transform each item
- `.filter()` - Keep only items matching condition
- `.find()` - Get first item matching condition
- `.reduce()` - Combine items into single value

**Lesson:** Master array methods - they're fundamental to React/TypeScript.

### 3. State vs. Variables
```typescript
// Variable - computed from loaded data
const loadedConversations = await getUserConversations(user.id);

// State - persists across renders
const [conversations, setConversations] = useState<Conversation[]>([]);

// Use variable immediately after loading
const latest = loadedConversations[0];

// State updates asynchronously
setConversations(loadedConversations);
// conversations is still old value here!
```

**Lesson:** Don't rely on state immediately after setting it. Use the variable.

### 4. TypeScript Types Are Contracts
```typescript
Promise<{ message: string }>
```

This tells everyone:
- Callers: "You'll get an object with a message property"
- Implementers: "You must return that shape"
- TypeScript: "I'll check this at compile time"

**Lesson:** Types document your code and prevent bugs.

### 5. Layout with Flexbox
Modern layouts use flexbox:
- `flex` - Enable flexbox
- `flex-col` - Vertical stacking
- `flex-1` - Take remaining space
- `justify-between` - Space items apart
- `items-center` - Center vertically

**Lesson:** Learn flexbox - it's the foundation of modern web layouts.

### 6. Callbacks Connect Components
Parent passes functions to child → Child calls them → Parent handles logic.

This pattern:
- Keeps components reusable
- Separates UI from logic
- Makes testing easier

**Lesson:** Props down, callbacks up - the React data flow.

### 7. Small Functions Are Better
```python
# Bad - one giant function
def create_conversation():
    # 100 lines of code...

# Good - break into smaller functions
def generate_title(messages):
    # 10 lines

def create_conversation():
    title = generate_title(messages)
    # Use title...
```

**Lesson:** Small, focused functions are easier to understand and test.
