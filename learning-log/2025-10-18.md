## RAG Concepts Learned

### What is RAG (Retrieval Augmented Generation)?

**The Problem RAG Solves:**
- LLMs have limited knowledge (only what they were trained on)
- LLMs can hallucinate (make up false information)
- You want answers based on YOUR specific data

**The RAG Solution (3 Steps):**

```
1. RETRIEVAL
   User asks: "How do I reset my password?"
   ↓
   Convert question to embedding (vector of 384 numbers)
   ↓
   Search vector database for similar embeddings
   ↓
   Retrieve top 3 most relevant articles

2. AUGMENTATION
   Take user's question + retrieved articles
   ↓
   Build a prompt that includes:
   - The question
   - The relevant article content
   - Instructions for the LLM

3. GENERATION
   Send prompt to LLM (Ollama Llama 3.2)
   ↓
   LLM generates answer BASED ON the articles
   ↓
   Return answer + sources to user
```

**Why RAG is Powerful:**
- Answers are grounded in YOUR data (no hallucination)
- Works with any domain (customer support, legal docs, medical records)
- Can update knowledge base without retraining the LLM
- Provides source citations (shows which articles were used)

### 1. Embeddings (Text → Numbers)

**What are embeddings?**
- Convert text into vectors (arrays of numbers)
- Similar meaning → similar numbers
- Enables "semantic search" (search by meaning, not just keywords)

**Example:**
```
"Reset password"     → [0.23, -0.45, 0.78, ..., 0.12]  (384 numbers)
"Password recovery"  → [0.25, -0.43, 0.76, ..., 0.14]  (very similar!)
"Export data"        → [0.89, 0.12, -0.34, ..., 0.67]  (very different!)
```

**Our Embedding Model:**
- `all-MiniLM-L6-v2` from sentence-transformers
- Converts text to 384-dimensional vectors
- Small (~90MB), fast, accurate
- Runs locally on CPU

**Code:**
```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')
embedding = model.encode("How do I reset my password?")
# Returns: array of 384 numbers
```

### 2. Vector Database (ChromaDB)

**What is a vector database?**
- Stores embeddings (vectors)
- Performs similarity search (find closest vectors)
- Uses cosine similarity to measure "closeness"

**Why not just use a regular database?**
- SQL databases search by exact match: `WHERE title = 'password'`
- Vector databases search by meaning: "Find articles similar to this question"

**ChromaDB Concepts:**
- **Client**: The database instance
- **Collection**: Like a table in SQL (stores related embeddings)
- **Documents**: The original text
- **Embeddings**: The vector representations
- **Metadata**: Additional info (title, category, tags)

**Code:**
```python
import chromadb

# Initialize database
client = chromadb.Client()

# Create collection
collection = client.get_or_create_collection(name="knowledge_base")

# Add documents with embeddings
collection.add(
    ids=["kb-001"],
    embeddings=[[0.23, -0.45, ...]],  # 384 numbers
    documents=["How to Reset Your Password\n\n..."],
    metadatas=[{"title": "Password Reset", "category": "Account"}]
)

# Search for similar documents
results = collection.query(
    query_embeddings=[[0.25, -0.43, ...]],  # User's question embedding
    n_results=3  # Return top 3 matches
)
```

**Similarity Search:**
- ChromaDB uses **cosine similarity** to find closest matches
- Distance = 0 means identical
- Distance > 0 means less similar
- Returns results sorted by distance (closest first)

### 3. Semantic Search vs Keyword Search

**Keyword Search (Traditional):**
```
Query: "forgot password"
Results: Only finds articles containing "forgot" AND "password"
Misses: "Password recovery", "Reset credentials", "Account access"
```

**Semantic Search (RAG):**
```
Query: "forgot password"
Embedding: [0.23, -0.45, 0.78, ...]
Results:
  1. "How to Reset Your Password" (distance: 0.12)
  2. "Password Recovery Guide" (distance: 0.18)
  3. "Account Access Issues" (distance: 0.24)
Finds: Articles with SIMILAR MEANING, even if words don't match!
```

**Real-world example from today:**
- Query: "I forgot my password"
- Found: "How to Reset Your Password"
- Words don't match exactly, but meaning is the same! ✅

### 4. Prompt Engineering

**What is prompt engineering?**
- How you phrase instructions to the LLM affects answer quality
- We give the LLM context (retrieved articles) and instructions

**Our Prompt Structure:**
```python
prompt = f"""You are a helpful customer support assistant.
Answer the user's question based on the following knowledge base articles.

Knowledge Base Articles:
{context}  # ← The 3 relevant articles

User Question: {query}

Instructions:
- Answer based ONLY on the information in the articles above
- If the articles don't contain relevant information, say "I don't have information about that in my knowledge base"
- Be concise and helpful
- Cite which article(s) you used if relevant

Answer:"""
```

**Why this works:**
- **Role**: "You are a helpful customer support assistant" → Sets tone
- **Context**: Provides the retrieved articles → Grounds the answer
- **Constraints**: "ONLY on the information in the articles" → Prevents hallucination
- **Fallback**: "I don't have information..." → Handles out-of-scope questions
- **Citations**: "Cite which article(s)" → Provides transparency

**Result:** The LLM stays grounded in your data and doesn't make things up!

## TypeScript/Frontend Concepts

### No Changes to Frontend!

One of the powerful things about APIs is that we completely changed the backend logic (from placeholder to RAG), but the frontend didn't need any changes!

**Why?**
- The API contract stayed the same:

## What We Learned About AI/ML

### 1. RAG vs Fine-Tuning

**RAG (what we built):**
- Retrieves relevant docs and includes them in the prompt
- No model training needed
- Easy to update knowledge (just add new articles)
- Cost: $0 with local models, ~$15/month with OpenAI

**Fine-Tuning (alternative):**
- Train the LLM on your data
- Expensive and time-consuming
- Hard to update (need to retrain)
- Cost: $1000s

**Conclusion:** RAG is better for most use cases!

---

### 2. The Importance of Vector Databases

**Why not just put all articles in the prompt?**
- LLMs have token limits (context windows)
- GPT-4: ~128K tokens (but expensive)
- Llama 3.2: ~8K tokens
- Our 8 articles = ~5000 tokens (close to limit!)

**With vector search:**
- Only send the top 3 most relevant articles
- Keeps prompts small and focused
- Cheaper (fewer tokens)
- Better answers (LLM focuses on relevant info)

---

### 3. Prompt Engineering Matters

**Bad prompt:**
```
Question: How do I reset password?
Articles: [all articles]
Answer:
```
Result: LLM might ignore articles, hallucinate, or give vague answer

**Good prompt (what we used):**
```
You are a customer support assistant.
Answer ONLY based on these articles.
If not in articles, say "I don't have information".
Cite which articles you used.

Articles: [relevant articles]
Question: How do I reset password?
Answer:
```
Result: Grounded, helpful, cited answer!
