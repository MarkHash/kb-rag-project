## Python/FastAPI Concepts Learned

### 1. FastAPI Application Setup
```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(
    title="KB RAG API",
    description="AI-powered knowledge base with RAG",
    version="1.0.0"
)
```
- FastAPI creates automatic API documentation
- Built-in validation with Pydantic
- Automatic OpenAPI/Swagger UI at `/docs`

### 2. CORS Middleware
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```
- **CORS** = Cross-Origin Resource Sharing
- Allows frontend (port 3000) to call backend (port 8000)
- Without CORS, browser blocks requests from different origins
- Required for frontend-backend communication

### 3. Pydantic Models
```python
class QueryRequest(BaseModel):
    """Request body for chat queries"""
    query: str

class QueryResponse(BaseModel):
    """Response body for chat queries"""
    answer: str
    sources: list[Article]
```
- Similar to TypeScript interfaces
- Automatic validation of request/response data
- Type safety in Python
- Auto-generates JSON schema for API docs

### 4. Path Operations (Decorators)
```python
@app.get("/")
async def root():
    return {"message": "KB RAG API is running"}

@app.post("/chat", response_model=QueryResponse)
async def chat(request: QueryRequest):
    return {"answer": "...", "sources": [...]}
```
- `@app.get()` - Handles GET requests
- `@app.post()` - Handles POST requests
- `response_model` - Validates and documents response type
- `async def` - Asynchronous function for better performance

### 5. Path Parameters
```python
@app.get("/articles/{article_id}")
async def get_article(article_id: str):
    # article_id comes from URL
    for article in KNOWLEDGE_BASE:
        if article['id'] == article_id:
            return article
```
- `{article_id}` in decorator = path parameter
- Extracted from URL automatically
- Type-safe with Python type hints

## TypeScript Concepts Learned

### 1. Promise Type with Generics
```typescript
export async function sendChatMessage(query: string): Promise<{
  answer: string;
  sources: Array<{...}>;
}>
```
- `Promise<Type>` = "Will return `Type` data eventually"
- Used for asynchronous operations
- Generic type parameter tells TypeScript what data to expect
- Enables type-safe async code

### 2. Fetch API
```typescript
const response = await fetch(`${API_BASE_URL}/chat`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ query }),
});
```
- `fetch()` - Browser's built-in HTTP client
- Returns a Promise
- `await` - Waits for Promise to complete
- `JSON.stringify()` - Converts JavaScript object to JSON string

### 3. Error Handling with Try-Catch-Finally
```typescript
try {
  const response = await sendChatMessage(newMessage.text);
  // Success: Add AI response
} catch (error) {
  // Error: Show error message to user
  console.error('Chat error:', error);
} finally {
  // Always runs: Stop loading state
  setIsLoading(false);
}
```
- `try` - Attempt the code
- `catch` - Handle errors if they occur
- `finally` - Always runs (even if error), perfect for cleanup

### 4. Type Definitions for Backend Data
```typescript
export type Source = {
  id: string;
  title: string;
  content: string;
  category: string;
  tags: string[];
};

export type ChatResponse = {
  answer: string;
  sources: Source[];
  conversationId: string;
};
```
- Match backend Pydantic models
- Ensures type safety across frontend-backend boundary
- TypeScript can catch mismatches at compile time

### Challenge 5: 422 Unprocessable Entity Error (THE BIG ONE!)
**Problem:** Backend returning 422 error for all /chat requests

**Error in logs:**
```
INFO:     127.0.0.1:56947 - "POST /chat HTTP/1.1" 422 Unprocessable Entity
```

**Debugging Process:**
1. Opened browser DevTools > Network tab
2. Inspected failed /chat request
3. Checked Payload: `{query: "hi"}` ✅ Correct!
4. Checked Response tab:
```json
{
  "detail": [{
    "msg": "Input should be a valid dictionary or object to extract fields from",
    "input": "{\"query\":\"hi\"}"
  }]
}
```
5. **Key observation:** Input was a STRING `"{\"query\":\"hi\"}"` not an OBJECT!
6. Checked `client.ts` Content-Type header
7. **Found the culprit:** `'applicatioin/json'` - missing 'n' in "application"!

**Solution:** Fixed typo to `'application/json'`

**Root Cause:** When Content-Type is wrong, the browser doesn't parse the body as JSON, so it sends it as a string. FastAPI then receives `"{\"query\":\"hi\"}"` (string) instead of `{"query": "hi"}` (object).

**Learning:**
- Always check HTTP headers when debugging API issues
- Browser DevTools Network tab is invaluable for debugging
- FastAPI error messages are very helpful - read them carefully!
- Small typos can cause big problems

## Key Takeaways

### 1. Full-Stack Integration Requires Matching Contracts
Frontend and backend must agree on:
- API endpoint URLs
- Request/response data structure
- Field names (query, answer, sources)
- Data types

### 2. Type Safety Across the Stack
- **Backend:** Pydantic models validate data
- **Frontend:** TypeScript interfaces enforce types
- **Together:** Catch errors before runtime

### 3. CORS is Essential for Frontend-Backend Communication
Without CORS middleware, browsers block cross-origin requests for security. Always configure CORS when frontend and backend are on different ports/domains.

### 4. Debugging with Browser DevTools
The Network tab shows:
- Request method and URL
- Headers (including Content-Type!)
- Request payload
- Response data
- Status codes

**This is the #1 tool for debugging API issues!**

### 5. FastAPI Automatic Documentation is Powerful
- `/docs` gives interactive API testing
- No need to write separate API documentation
- Auto-generated from Python type hints

### 6. Small Typos Can Break Everything
Today's typos:
- `applicatioin` → `application` (Content-Type header)
- `totle` → `title` (type definition)
- `newMessage.ext` → `newMessage.text` (property access)

**Always double-check spelling, especially in field names and headers!**

### 7. Error Messages Are Your Friends
FastAPI's 422 error told us exactly what was wrong:
> "Input should be a valid dictionary or object to extract fields from"

Read error messages carefully - they often point to the exact problem.

### 8. Async/Await Makes Async Code Look Synchronous
```typescript
// Looks synchronous, but is actually async
const response = await sendChatMessage(query);
const aiResponse = { text: response.answer };
```
Much easier to read than Promise chains!

### 9. Try-Catch-Finally for User Experience
- `try` - Attempt the operation
- `catch` - Show user-friendly error message
- `finally` - Always stop loading indicator

Good error handling makes your app feel professional.
