## TypeScript Concepts Learned

### 1. Type Assertions with `as`
When loading data from external sources (API, database), you often need to tell TypeScript the specific type:

```typescript
const messagesWithDates = latestConversation.messages.map((msg) => ({
  ...msg,
  timestamp: new Date(msg.timestamp),
  sender: msg.sender as 'user' | 'assistant' | 'system', // ← Type assertion
}));
```

**Why:** Database returns generic `string`, but our type expects specific union type `'user' | 'assistant' | 'system'`.

### 2. Avoiding `any` Type
TypeScript strict mode doesn't allow `any` types in production. Always use specific types:

```typescript
// ❌ Bad
messages: any[]

// ✅ Good
messages: Message[]

// ✅ Also good for inline types
sources?: Array<{
    id: string;
    title: string;
    content: string;
    category: string;
    tags: string[];
}>
```

### 3. React Hook Dependencies - Deep Dive
The dependency array tells React when to re-run the effect:

```typescript
useEffect(() => {
  const loadConversations = async () => {
    if (isLoaded && user) {  // ← Using isLoaded and user
      const conversations = await getUserConversations(user.id);
      // ...
    }
  }
  loadConversations();
}, [isLoaded, user]); // ← MUST list all variables used inside
```

**Rule:** Any variable from outside the effect that's used inside MUST be in the dependency array.

**What happens:**
- Component mounts → Effect runs
- `isLoaded` changes from `false` to `true` → Effect re-runs
- `user` changes from `null` to user object → Effect re-runs → Loads data! ✅

### 4. Function Declaration Inside vs Outside useEffect

**Inside useEffect** (what we used):
```typescript
useEffect(() => {
  const loadConversations = async () => {
    // ...
  };
  loadConversations();
}, [isLoaded, user]);
```
✅ Simple - function only used in this effect
✅ No extra dependencies to manage

**Outside with useCallback** (for reusable functions):
```typescript
const loadConversations = useCallback(async () => {
  // ...
}, [isLoaded, user]);

useEffect(() => {
  loadConversations();
}, [loadConversations]);
```
✅ Can reuse in multiple places (button, another effect)
⚠️ More complex - two dependency arrays to maintain

**Rule of thumb:** Keep functions inside useEffect unless you need to reuse them.

## Challenges Faced

### Challenge 1: TypeScript Linting Errors Blocking Deployment
**Problem:** Vercel build failed with:
```
Error: Unexpected any. Specify a different type. @typescript-eslint/no-explicit-any
```

**Solution:**
- Replaced `any[]` with proper types (`Message[]`, inline Source type)
- Added `import { Message } from './types'` to client.ts
- Used explicit types for all function parameters

**Lesson:** Production builds enforce stricter TypeScript rules than development. Always use specific types, never `any`.

### Challenge 2: Missing Clerk Environment Variables
**Problem:** Vercel deployment failed:
```
Error: @clerk/clerk-react: Missing publishableKey
```

**Solution:**
- Added Clerk environment variables in Vercel dashboard
- Set for Production, Preview, and Development environments
- Redeployed

**Lesson:** Environment variables in `.env.local` are local only - must configure them in hosting platform (Vercel, Railway).

### Challenge 3: Railway 404 on /conversations Endpoints
**Problem:**
- Backend deployed successfully
- `/chat` endpoint worked (200 OK)
- `/conversations` endpoints returned 404 Not Found
- No error logs

**Root Cause:** Database dependencies missing from `requirements.txt`, causing silent import failures.

**Solution:**
- Added `sqlalchemy==2.0.23` and `psycopg2-binary==2.9.9` to requirements.txt
- Added DATABASE_URL validation in database.py to catch missing env vars early
- Redeployed

**Lesson:** When endpoints return 404 but server starts fine, check for import errors. Silent failures happen when dependencies are missing.

### Challenge 4: Python 3.13 Compatibility Issue
**Problem:** Railway deployment crashed with:
```
AssertionError: Class <class 'sqlalchemy.sql.elements.SQLCoreOperations'>
directly inherits TypingOnly but has additional attributes
```

**Root Cause:** Railway used Python 3.13 by default, but SQLAlchemy 2.0.23 doesn't support Python 3.13's new typing features.

**Solution:**
- Created `backend/railway.toml` to specify Python 3.11:
```toml
[build]
builder = "nixpacks"

[build.nixpacksPlan]
providers = ["python"]

[build.nixpacksPlan.phases.setup]
nixPkgs = ["python311"]
```

**Failed Attempts:**
- `.python-version` file → "invalid config file extension"
- `runtime.txt` → "invalid config file extension: .txt"

**Lesson:** Each hosting platform has its own config format. Railway uses `railway.toml`, not Heroku-style `runtime.txt`.

### Challenge 5: Railway Root Directory Configuration
**Problem:** Railway couldn't find the app:
```
✖ Railpack could not determine how to build the app
The app contents that Railpack analyzed contains:
./
├── backend/
├── frontend/
```

**Solution:** Set "Root Directory" to `backend` in Railway Settings → Build & Deploy.

**Lesson:** For monorepo projects, specify which subdirectory contains the deployable app.

### Challenge 6: Conversations Not Loading After Refresh (IN PROGRESS)
**Problem:**
- Conversations save to database ✅
- But on refresh, app creates a NEW conversation instead of loading the existing one ❌

**Root Cause (Hypothesis):** Race condition between loading and saving:
1. Page loads with initial welcome message
2. Loading effect starts fetching conversations
3. Saving effect triggers (because messages changed)
4. Save happens BEFORE conversationId is set
5. Creates new conversation instead of waiting for load

**Next Steps for Tomorrow:** Add loading state flag to prevent saving during data load.

## Key Takeaways

### 1. Type Safety is Critical in Production
Development mode is forgiving, but production builds enforce strict TypeScript rules. Always:
- Use explicit types, never `any`
- Add type assertions when loading external data
- Import and reuse type definitions instead of duplicating

### 2. Environment Variables Must Be Set in Hosting Platform
`.env` files are local only. For production:
- Vercel: Settings → Environment Variables
- Railway: Variables tab
- Always set for all environments (Production, Preview, Development)

### 3. React Hook Dependencies Are Non-Negotiable
If you use a variable inside `useEffect`, it MUST be in the dependency array. Trust the ESLint warning.

### 4. Silent Failures Are Hard to Debug
When endpoints return 404 but server starts fine:
1. Check import errors (missing dependencies)
2. Check if endpoints are being registered
3. Look at auto-generated API docs (`/docs` in FastAPI)
4. Add explicit error handling/validation

### 5. Python Version Compatibility Matters
Always check compatibility between:
- Python version
- SQLAlchemy version
- Other dependencies

Use stable versions (3.11, 3.12) instead of bleeding edge (3.13) for production.

### 6. Each Platform Has Its Own Config Format
- Heroku: `runtime.txt`, `Procfile`
- Railway: `railway.toml`
- Vercel: `vercel.json`
- Netlify: `netlify.toml`

Don't assume they're interchangeable!

### 7. Race Conditions in React State Updates
When multiple state updates happen simultaneously (load + save), order matters:
- Use flags to coordinate async operations
- Prevent saves during loads
- Use cleanup functions in useEffect when needed
